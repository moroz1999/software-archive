# Интеграция Typesense в архив софта

PostgreSQL — источник данных для CRUD и полных карточек. Typesense обслуживает общий поиск и каталог с фильтрами. React обращается к API бэкенда.

## Поиск и каталог

- **Общий поиск.** Один `multi_search` по коллекциям `authors`, `programs`, `groups` с одним ключевиком. Для каждой секции вернуть результаты, количество совпадений и независимую пагинацию.
- **Каталог софта.** Использовать ту же коллекцию `programs`, по одному документу на программу. Хранить в документе поля карточки и значения фильтров. Передавать выбранные условия через `filter_by`, а год, категорию и страну запрашивать через `facet_by`. При пустом поиске использовать `q=*`. Возвращать страницу и доступные значения со счётчиками по всей отфильтрованной выдаче. Задать `max_facet_values` под интерфейс.
- Если интерфейс позволяет сразу переключить активное значение, посчитать варианты этого фильтра отдельным запросом без его собственного условия. Остальные условия и ключевик сохранить. Запросы объединить через `multi_search`.

## Синхронизация

1. В той же транзакции PostgreSQL, что и изменение данных, добавить в `search_outbox` тип и ID каждой сущности, чей поисковый документ изменился. Учесть связанные документы. Например, при переименовании автора обновить и программы, если в их карточках хранится имя автора.
2. Один фоновый воркер обрабатывает задачи после коммита. Для каждой задачи читает актуальные данные из PostgreSQL и делает `upsert` полного документа со стабильным ID. Если записи больше нет или она исключена из публичной выдачи, удалить документ. Отсутствующий документ считать успешным удалением.
3. Подтверждать задачу только после успешной операции. При сбое сохранить её для повтора с задержкой. CRUD завершается после коммита PostgreSQL, а поисковая выдача обновляется асинхронно.

## Первичная загрузка и пересборка

Сделать CLI-команду, которая читает PostgreSQL, использует те же правила сборки документов, что и воркер, и загружает документы пакетами в новые коллекции. Проверить результат импорта каждого документа и переключить алиасы только после успешной загрузки всех коллекций.

На время загрузки приостановить воркер до начала чтения PostgreSQL. Запись задач в outbox продолжается. После переключения алиасов возобновить обработку накопившихся изменений. При ошибке загрузки сохранить прежние алиасы и возобновить воркер.

## Проверка результата

- Переход на вторую страницу программ сохраняет текущие страницы авторов и групп.
- После выбора года категории и страны сужаются по всем совпадениям, в том числе по программам на следующих страницах.
- При недоступном Typesense правка сохраняется в PostgreSQL. После восстановления воркер применяет правку или удаление к индексу.
